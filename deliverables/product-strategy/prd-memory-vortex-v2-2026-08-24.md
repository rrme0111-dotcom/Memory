## 第1章 产品目标

v1.0 原有的3场景架构升级为4场景，目标随之从"覆盖情感记录"进化为"覆盖全生命周期情感记忆"。以下3个目标两两正交，互不包含：

### 目标1：打造唯一"自定义时间戳+感受留言"情感记忆引擎（功能深度目标）
在照片/视频之上叠加"真实感受文本"与"可回拨的自定义时间戳"，使用户能回到任意历史瞬间的真实情绪。**自定义时间戳是全行业0竞品空白维度**，是本产品最深的技术与体验护城河。所有4场景共享此引擎。

**衡量方式：**
- 自定义时间戳使用率 ≥ 40%
- 周活跃高质量记忆创作者数 ≥ 5万（北极星指标）

### 目标2：构建"共建系统"复用架构——情侣+友情同一套共建能力（系统效率目标）
将情侣共建与友情共建合并为同一套"共建系统"（共享时间线、互相留言、多视角、邀请伙伴），通过场景分层（关系类型=参数）实现复用降本。区别仅在关系结构参数：情侣=1对1排他、好友=可群组。**竞品已验证此架构可行，但无一做到场景分层。**

**衡量方式：**
- 共建空间创建率 ≥ 35%
- 情侣向7日内邀请伙伴成功率 ≥ 60%

### 目标3：建立"场景选择器→多场景聚合"的全生命周期记忆入口（用户LTV目标）
通过场景选择器统一入口 + 个人中心聚合视图，让用户在个人→情侣→友情→成长四个场景间平滑迁移，单用户LTV从"单场景使用"拉长为"全生命周期覆盖"。**0竞品卡位此架构。**

**衡量方式：**
- 多场景用户占比（使用≥2场景）≥ 20%
- 场景分布健康度（无单一场景>60%）

> **三目标正交性说明**：目标1是"功能深度"（向下做深），目标2是"系统复用"（横向做广），目标3是"生命周期覆盖"（纵向拉长）。任一目标独立成立，且三者组合构成不可复制的竞争壁垒。

## 第2章 用户故事

### US-1 个人记录（个人场景）
> 作为林薇，我想用自定义时间戳标注当时真实感受，以便多年后按真实时间线回到那个瞬间的情绪。

**场景**：独居白领深夜整理情绪，给一张老照片补填过去的真实日期，让它在时间轴上回到属于它的位置。

### US-2 情侣共建（共建系统·情侣）
> 作为陈昊，我想和苏苏共建一条双人记忆线并互相留言，以便异地恋中制造惊喜与陪伴感。

**场景**：异地情侣纪念日互写"未来信"，各自视角记录同一事件。

### US-3 友情共建（共建系统·友情，新增）
> 作为苏然，我想邀请小鹿共同维护一条记忆线，以便异地死党每年聚会后拼出完整的集体回忆，而不是各自零散保存。

**场景**：大学室友毕业分散两地，每年聚会后共建记忆线，生日互相留言，毕业5周年回看老照片。

### US-4 成长追踪（成长场景，重构为非共建）
> 作为王悦，我想为宝宝和宠物分别建立独立成长时间轴，以便系统自动归类里程碑并对比两者的成长轨迹。

**场景**：新手妈妈为1岁宝宝和家猫分别建独立轴，记录身高/第一句话/第一次走路，按主体自动归类。

### US-5 纪念日（跨场景·共建+个人）
> 作为陈昊，我想在纪念日当天自动推送我提前预留的留言给苏苏，以便制造仪式感惊喜。

**场景**：恋爱3周年前一周写好留言，系统在纪念日当天定时推送到对方。

### US-6 自定义时间戳（跨场景·全场景共享）
> 作为林薇，我想给一张老照片补填过去的真实日期，以便它在时间轴上回到属于它的位置。

**场景**：翻到3年前拍的旧照，将日期回拨到拍摄当天，时间轴自动插入对应位置。

### 3.2 关键画像洞察

**共建心智模型统一性**：情侣共建与友情共建共用同一套"共建系统"在用户认知上成立——心智模型是"我和某个人共建"，区别仅在"那个人是伴侣还是朋友"，功能诉求一致。

**成长场景独立的语义纠偏**：成长场景独立是因为心智模型是"我独自追踪某个对象的成长"，对象（宝宝/宠物）不会反向留言，共建无意义。7款成长App竞品无一采用双视角共建，验证了此判断。

### 3.3 用户旅程（跨场景迁移路径）

```
林薇个人记录(个人场景)
  → 恋爱后邀请伴侣共建(情侣场景)
  → 仍和大学室友维护友情线(友情场景)
  → 生子后为宝宝建独立轴(成长场景)
  → 同时养猫，为猫建独立轴(成长场景·多主体)

  全程在个人中心聚合视图看到"生活全貌"
```

> 此旅程说明：用户会同时使用多场景，是关键留存信号。建议将"同时使用≥2场景"列为北极星指标之一。

### 3.4 场景选择器交互验证

- **认知负荷**：4选项处于认知负荷临界点（>5-7项才显著增加决策疲劳），可接受但需主动降低成本
- **降低成本策略**：
  1. 情感化图标呈现而非功能列表（个人→独处剪影、情侣→双人、友情→多人、成长→人物轮廓）
  2. 默认推荐上次使用/最常用场景
  3. 渐进解锁——首次只亮2个核心场景（个人+情侣），友情/成长在用户有共建/育儿行为后浮现
- **影响预测（数析数据）**：首次完成率预计60-70%（下降5-10%），但首日留存+10-15%、D7留存+5-8%。**净正向**。

### 3.5 个人中心聚合视图需求

- **用户矛盾**：既要"一眼看全部"又要"按场景切"
- **解决方案**：双视图并存
  - 默认分场景Tab（保证情感语境清晰）
  - 可选"全场景时间轴"（满足多场景用户按真实时间回看生活全貌）
- **首屏设计**：个人中心首屏以分场景Tab为主，顶部常驻"全部记忆"入口
- 多场景用户活跃后引导发现聚合视图，反哺多场景留存

### 4.2 三大市场空白

1. **自定义时间戳全行业空白**：10款竞品无一支持任意回拨历史日期，9款为❌，1款(DayOne)仅⚠️部分支持
2. **"情侣共建+友情共建+成长独立"三系统同App = 0竞品**：5/9款已验证共建通用化可行，但无一同时覆盖成长独立
3. **场景选择器+聚合视图 = 0竞品**：全行业无统一入口解决"跨关系记忆碎片化"

### 4.3 差异化策略（6条）

| # | 策略 | 竞品空白 |
|---|------|---------|

| D2 | 情侣+友情共用共建系统——复用降本、场景分层增值 | 竞品先例验证可行但未做场景分层 |

| D6 | "往年今日"跨场景编织 | 单一场景竞品结构上无法复制 |

### 4.4 护城河（三层加固）

**第1层：场景网络效应（锁定LTV）**
4场景覆盖全生命周期，用户从个人→情侣→成长平滑迁移，单用户LTV拉长。场景越多，迁移成本越高。

**第2层：数据迁移壁垒**
聚合视图+自定义时间戳的历史数据迁到单一场景竞品会丢跨场景上下文，用户"搬不走"。

**第3层：共建通用化先发细分**
若率先占"情感记忆统一入口"心智，后来者须同时复制4套系统（个人+共建+成长+聚合），门槛极高。

```
   │                                                    ↓

          └── [宠物独立轴] → 照片+里程碑标注+感受留言 → 自动里程碑识别 → 成长对比(then vs now)
                               ↓
                    [所有场景记忆] → [个人中心聚合视图]
                                        ├── 分场景Tab视图（默认）
                                        ├── 全场景时间轴（按真实时间戳）
                                        └── 往年今日（跨场景编织）
                                                    ↓
                                            [数据沉淀·多场景留存信号]
```

### 7.2 新建记忆详细流程

```
1. 用户点击"+"新建 → 场景选择器弹出
2. 选择场景：
   - 个人 → 直接进入记忆编辑页
   - 情侣/友情 → 检查是否有共建空间
     - 有 → 选择共建空间 → 进入记忆编辑页
     - 无 → 引导创建共建空间 → 邀请伙伴 → 进入记忆编辑页
   - 成长 → 选择成长主体 → 进入记忆编辑页
3. 记忆编辑页（全场景统一）：
   - 上传照片/视频
   - 编写感受留言（必填）
   - 设置自定义时间戳（默认当前，可回拨）
   - [成长场景额外] 选择里程碑类型
   - [共建场景额外] 选择视角归属
4. 保存 → 记忆按时间戳插入对应时间轴 → 聚合视图同步更新
```

### 7.3 纪念日流程

```
1. 在共建空间/个人中心 → 设置纪念日（日期+名称）
2. 预留留言（提前写好文本）
3. 设置"纪念日当天推送"
4. 系统定时任务 → 纪念日当天 → 推送到对方/自己
5. 接收方看到仪式感推送 → 查看留言 → 回顾关联记忆
```

### 9.1 优先级调整建议（来自路径+析客）

**建议1：将REQ-013场景渐进解锁（3pd）从P1提到MVP**
4场景同时暴露认知负荷过高，直接威胁MVP成功指标"场景分布健康度"和"首次完成率65%"。仅3pd，ROI极高。调整后MVP为77pd，仍在产能窗口内。

**建议2：保留共建系统(REQ-003,18pd)和成长追踪(REQ-004,15pd)同在MVP，但严格排序**
两者合计33pd占MVP的45%，后端负载集中。但架构上成长场景是独立追踪（非共建），与共建系统零耦合，可作独立工作流推进。建议共建系统优先（复用情侣+友情两场景，ROI最高），成长追踪第二优先并行推进。若后端进度告急，成长追踪可安全推迟到V1.1而不影响共建核心体验。

**建议3：REQ-001场景选择器必须在Phase 0用原型验证**
所有场景的入口，用户不理解场景模型则产品前提崩塌。建议Phase 0用2-3天做可点击原型跑5-8人测试。最高杠杆风险对冲动作。

**建议P0开发顺序**：REQ-007时间戳引擎 → REQ-001场景选择器 → REQ-002个人记忆 → (REQ-003共建 ∥ REQ-004成长) → REQ-005聚合视图 → REQ-006纪念日
