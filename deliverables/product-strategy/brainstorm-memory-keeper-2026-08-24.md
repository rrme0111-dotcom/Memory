## 创意清单（已基于竞品+用户洞察验证）

### 方向一：情感记忆博物馆（个人向）

**一句话定位**：你的私人情感时间轴——每条记忆都是"媒体+当时感受+你的时间戳"的完整单元。

| 维度 | 内容 |
|------|------|
| 目标用户 | 个人日记/情绪记录爱好者、独居年轻人、旅行记录者 |
| 核心场景 | 深夜emo时刻随手拍+语音留言还原语气；独自旅行中录下比打字更真实的感受；回看"一年前的今天"那条带声音的记忆 |
| 核心差异 | **自定义时间戳（回溯/前注）**是全行业空白——日记App默认当天、倒计时类只算"距今N天"、社交按发布时间。本方向独占"记忆时序≠文件时序"的能力 |
| 竞品依据 | 格志日记/Day One有感受无纪念日；倒数日有纪念日无感受；社交平台受社交压力绑架不敢真实表达。无人整合四合一 |
| 商业模式 | 基础免费+Pro订阅（云端存储扩容、语音转文字、导出记忆漩涡） |
| MVP范围 | 导入照片/视频 → 添加文字/语音留言 → 自定义时间戳 → 标记纪念日 → 时间轴回看 + "X年前的今天"推送 |
| 风险 | 用户教育成本："自定义时间戳"需通过引导让用户理解价值 |

---

### 方向二：关系记忆共建（双人向）

**一句话定位**：两个人，一条记忆线——把"我们的故事"变成可回听的情感时间轴。

| 维度 | 内容 |
|------|------|
| 目标用户 | 情侣/伴侣（含异地恋）、新婚夫妇 |
| 核心场景 | 约会后随手拍+留言当下心动；异地恋语音说晚安+标记"在一起第100天"；纪念日点开即回顾当年那条带感受的记录 |
| 核心差异 | 比恋爱记更注重**感受还原**（语音留言+情绪标签），而非打卡攒钱等社交功能堆叠；自定义时间戳解决异地恋时差导致的记录错位 |
| 竞品依据 | 恋爱记5000万用户验证需求存在，但功能大而全、感受深度不够；Between已式微；社交平台无私密性 |
| 商业模式 | 双人共建免费+关系订阅（情侣主题包、纪念日定制卡片、双人记忆漩涡导出） |
| MVP范围 | 双人绑定空间 → 共同导入媒体+各自留言 → 自定义时间戳 → 共享纪念日标记 → "我们的时间轴"回看 |
| 风险 | 强绑定"双人关系"场景，单人体验缺失；关系变动（分手）后的数据归属需设计 |

---

### 方向三：成长里程碑管家（家庭/宠物向）

**一句话定位**：成长太快，留住每一刻的心跳——面向宝宝和宠物的成长记忆漩涡。

| 维度 | 内容 |
|------|------|
| 目标用户 | 年轻父母（0-3岁宝宝）、宠物主人 |
| 核心场景 | 宝宝第一次翻身/走路时录视频+语音激动留言；补记昨天漏拍的重要时刻（自定义时间戳回溯）；宠物离世后回看"3年前的今天它还那么小" |
| 核心差异 | 以**成长里程碑**为核心叙事结构，纪念日自动变身为"成长回顾"——点开即回放当年那条带感受的记录，而非只显示一个数字 |
| 竞品依据 | 相册只存图无感受；日记App照片是附属无语音；无产品整合"成长+感受+纪念日"；倒数日只显示数字不回溯内容 |
| 商业模式 | 免费+成长订阅（AI成长报告、里程碑提醒、实体记忆相册定制打印） |
| MVP范围 | 创建成长主体（宝宝/宠物）→ 导入媒体+语音/文字留言 → 自定义时间戳补记 → 标记里程碑纪念日 → "成长时间轴"+里程碑自动提醒 |
| 风险 | 需考虑多宝宝/多宠物场景；隐私合规（未成年人内容存储） |

## ⚠️ 待确认 / 假设 / Non-goals

**待确认**
- 产品形态优先级：App优先还是小程序优先？
- 语音留言是否需要实时语音转文字（影响技术方案和成本）？
- 数据存储策略：本地优先还是云端优先？

**假设**
- 目标用户对"自定义时间戳"概念有认知基础，可通过引导教育
- 用户愿意为"私密情感记忆"付费（而非用免费社交平台替代）

**Non-goals（本阶段明确不做）**
- ❌ 不做社交feed/信息流——这是私密记忆工具，不是社交平台
- ❌ 不做AI生成内容——记录真实感受，不生成虚拟感受
- ❌ 不做多平台内容聚合导入——聚焦核心记录体验，不做工具箱
