你是资深后端架构师。请为「记忆漩涡 MemoryVortex」App 设计并实现生产级后端，**硬性要求：高可用、高性能、安全合规**。

## 一、项目背景

「记忆漩涡」是一款多场景记忆记录 App，口号：把值得记住的瞬间，卷入记忆漩涡。前端交互原型已完成（16 屏），采用真假数据分离架构：`test_data.js` 模拟后端接口返回值，后端就绪后前端将 `DATA_MODE` 从 `'mock'` 切换为 `'api'`。**你的 API 响应结构必须与 test_data.js 中的数据形状对齐**（字段名、嵌套结构保持一致，前端才能零改动接入）。

## 二、功能需求（按模块）

1. **用户与账户**：注册/登录（手机号+验证码，预留微信登录）、个人信息、设置、登出。
2. **场景管理**：4 种场景——personal（个人博物馆，私密）、couple（情侣空间，1对1排他共建）、friend（友情空间，最多6人群组共建）、growth（成长追踪，为宝宝/宠物建立独立主体）。
3. **记忆条目（核心）**：
   - 内容：文字感受 + 多张照片/视频 + 一段语音；
   - 情绪标签（多选，如：想念/幸福/平静/孤独/感动/期待/疲惫/难过/焦虑）；
   - **时间戳双模式**：精确时间（年月日时分滚轮选择）与模糊时间（预设选项如「去年夏天」「大学时期」+ 可选自由补充描述），两种都要持久化；
   - 多视角：同一条记忆下，不同共建成员可各自发布自己的感受与语音；
   - 留言（评论）。
4. **共建与邀请**：邀请码生成与校验（如 Q7K-2024）、待接受/已加入状态流转、情侣空间排他绑定、友情空间成员上限。
5. **纪念日**：基于记忆标记纪念日、支持公历+农历、每年重复、倒计时计算（如「还有12天」「已过215天」）与推送提醒。
6. **成长追踪**：独立主体（宝宝/宠物）、自动归类里程碑（major 标记）、时间轴展示、同月龄对比。
7. **时间轴中心**：聚合视图（按日期分组的 timeline）、场景视图、情侣/友情专属时间线、**往年今日**（跨场景聚合不同年份同月同日的记忆）。
8. **推送通知**：纪念日提醒、共建邀请、新视角/新留言通知。

## 三、非功能需求（硬指标）

- **可用性 ≥ 99.9%**：无单点故障；核心链路多副本部署；数据库主从+自动故障转移；媒体上传失败可重试续传；优雅降级（推送/推荐等非核心服务不可用不影响记录功能）。
- **高性能**：API P95 < 200ms，P99 < 500ms；列表类接口（timeline/往年今日）需缓存与分页（游标分页）；单实例支撑 ≥ 1000 QPS，可水平扩展；目标规模：注册用户 100 万、DAU 10 万、人均 500 条记忆。
- **安全合规（重点，这是私密情感数据）**：
  - 传输 TLS 1.3；静态加密（数据库 TDE / 字段级加密敏感字段）；
  - 严格访问控制：记忆内容仅本人及被授权的共建成员可见，接口层必须校验关系权限，防水平越权（IDOR）；
  - 遵循《个人信息保护法》：隐私政策、账号注销与数据删除（软删除+定期物理清除）、数据导出能力；
  - 媒体文件私桶 + 签名 URL（短有效期）访问，严禁公开可枚举；
  - 防刷：验证码、登录/发布接口限流、内容审核（敏感词/图片审核，预留第三方审核回调）。
- **数据可靠性**：每日全量+增量备份，RPO ≤ 5 分钟，RTO ≤ 30 分钟，定期演练恢复。

## 四、架构要求

1. **整体架构**：给出架构图（文本/mermaid），说明网关、服务划分、数据流。初期建议「模块化单体 + 清晰领域边界」，预留拆分微服务的演进路径；说明理由。
2. **技术栈（可调项，默认推荐）**：
   - 后端：Node.js (NestJS) 或 Java (Spring Boot) 或 Go——【请指定其一】
   - 数据库：PostgreSQL（主）+ Redis（缓存/会话/限流/倒计时计算）
   - 消息队列：RabbitMQ 或 RocketMQ（通知异步化、内容审核解耦）
   - 对象存储：云 OSS/COS（私桶）+ CDN 回源签名
   - 部署：Docker + K8s（或 docker-compose 起步）+ Nginx/APISIX 网关
   - 可观测：结构化日志（ELK/Loki）、Prometheus + Grafana 指标、链路追踪（OpenTelemetry）
3. **数据库设计**：给出完整 DDL（含索引、约束、注释），核心表建议：users、scenes(user_scenes)、memories（含 timestamp_type、precise_at、fuzzy_label、fuzzy_note 字段）、memory_media、perspectives、comments、emotions、relations（couple/friend 统一建模）、invitations、anniversaries（含 lunar 标记）、growth_subjects、milestones、notifications。往年今日查询请设计 (user_id, month, day) 函数索引或生成列。所有表含 created_at/updated_at/deleted_at 软删除。
4. **API 设计**：REST，统一前缀 `/api/v1`，统一响应包 `{code, message, data}`；按模块列出全部接口清单（方法/路径/入参/出参/权限）；媒体上传采用「服务端签发预签名 URL → 客户端直传 OSS → 回调确认」三步流程，语音需转码（统一 AAC/MP3）与波形时长提取。
5. **高可用设计**：无状态服务多副本、健康检查与就绪探针、熔断降级（Resilience 模式）、Redis 缓存策略（Cache-Aside、纪念日倒计时用 ZSET）、定时任务（纪念日提醒/往年今日预计算，注意分布式锁防重复执行）、农历转换库选型。
6. **性能设计**：timeline 聚合的缓存与游标分页方案、共建成员变更是低频操作可缓存关系快照、媒体列表 URL 按需签发、慢查询治理与索引验证计划（EXPLAIN）。
